- The `download kernel` command now downloads the preimages of a kernel over a
  pool of connections, several at a time, instead of one at a time each on a
  connection of its own. On a kernel of ~2200 preimages this takes the command
  from about eighty seconds to about three. The new `--parallel-download`
  option sets how many preimages are fetched at a time, and how many
  connections are opened (8 by default); lower it for an endpoint that limits
  the number of requests it accepts.
- A preimage the endpoint cannot provide is now reported as an error naming the
  hash and the status code, instead of aborting the command with `Too many
  tries, aborting.`.
